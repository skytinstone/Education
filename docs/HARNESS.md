# 하네스 (Harness Engineering)

> 에이전트 = 모델 + 하네스. 하네스는 모델을 둘러싼 장치(맥락 · 도구 · 검증 · 피드백 · 가드레일 · 관측 · 평가)이고,
> 같은 모델로도 정확하고 안전하며 **측정 가능한** 시스템을 만드는 것이 목표다.

Eureka 의 LangChain · Tool Calling · RAG(→ [AI_AGENT.md](AI_AGENT.md))는 그대로 두고, 그 바깥에 하네스를 단계적으로 더한다.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | **관측 + 버전 관리** — 실행 추적(`agent_runs`), 프롬프트 레지스트리, 운영 콘솔 실행 타임라인 | ✅ |
| 2 | **평가** — 골든셋(정상 + 일부러 망가뜨린 문제), 결함 탐지율 · 오탐률 · 검산 정확도 · RAG 검색 정확도 · 비용, CI 회귀 + 정기 실측, 버전별 점수판 | ✅ |
| 3 | **자기 수정 루프** — 검증 지적 · 검산 결과를 생성 AI 에 되돌려 고치게, 효과는 2단계 평가로 측정 | ✅ |
| 4 | **가드레일 + 사람 검토** — 입력·출력 검사, AI 호출 차단기, 검토 큐 → 골든셋 | ✅ |

## 1단계 — 관측 + 버전 관리

### 프롬프트 레지스트리 (`harness/prompts.py`)
- AI 에게 주는 지시문 20개를 코드에서 `src/education/harness/prompts/<모듈>/<이름>.md` 로 옮겼다 (내용은 그대로 — 옮기기 전후 값이 같음을 확인).
- **버전 = 지시문 내용 해시 앞 8자리.** 글자 하나만 바꿔도 버전이 바뀐다 — 버전 번호를 손으로 올리지 않아도 어떤 지시문이 쓰였는지 정확하다.
- **하네스 버전** = 모든 지시문 버전 + 모델 설정(생성 · 검증 · 대화 모델과 추론 강도, 임베딩 모델)의 해시. 평가 점수를 이 버전끼리 비교한다.

### 실행 추적 (`harness/trace.py` → `agent_runs`)
실행 한 번마다 하네스 버전 · 이 실행에 쓴 지시문 버전 · 입력 요약 · 결과 · 단계별 기록 · 합계 비용과 시간을 남긴다.

| 실행 | 단계 |
|---|---|
| 문제 생성 (문제 한 개) | 생성 AI → 형식 검사 → 검증 AI(독립 재풀이) → 도구 호출(SymPy) → 검산 에이전트 판정 → RAG 중복 확인 · 재시도하면 단계가 이어서 쌓인다 |
| 대화 에이전트 (한 번) | 도구 호출(학습 현황 · 플래너 · 오답 · 문제 검색 · 계산) → 답 · 실패하면 `failed` 와 함께 한 번 답으로 돌아간 사실 |

단계에는 모델 · 토큰 · 비용 · 걸린 시간 · 도구 입력과 결과(앞부분)가 남는다. 기록이 실패해도 본 기능은 멈추지 않는다 (savepoint).

### 운영 콘솔 — AI 실행 기록 (`/admin#/runs`)
- 지금 하네스 버전 · 모델 · 지시문 버전 목록
- **버전별 결과**: 실행 수 · 통과/탈락/실패 · 평균 비용 · 평균 시간
- 실행 목록(종류 · 결과 필터) → **단계별 타임라인**

API: `GET /api/admin/harness`, `GET /api/admin/runs`, `GET /api/admin/runs/{id}` (운영자만).

## 2단계 — 평가 (Evals)

### 골든셋 (`harness/evals/golden/`)
- `verify.yaml` — 손으로 정답을 확인한 객관식 **좋은 문제 15개** + 일부러 망가뜨린 **나쁜 문제 13개**
  (정답 번호 오류 6 · 복수 정답 2 · 조건 누락 3 · 맞는 보기 없음 2). 정답 번호만 바꾼 문제는 같은 본문의 좋은 문제와 짝이다.
- `retrieval.yaml` — 학생 요청 같은 문장 6개와 기대 개념 (운영 문제 은행 기준).

### 무엇을 재나 (`harness/evals/runner.py`)
실제 문제 생성과 **같은 검사 층**(검증 AI → 계산 도구 검산 에이전트)에 골든셋을 통과시킨다.

| 지표 | 뜻 |
|---|---|
| detection_rate | 망가진 문제를 거른 비율 ↑ |
| false_reject_rate | 좋은 문제를 잘못 버린 비율 ↓ |
| verifier_detection / math_check_added | 검증 AI 혼자 거른 비율 / 검산 에이전트가 **추가로** 거른 비율 → Tool Calling 의 기여 |
| math_check_accuracy | 검산 에이전트 판단이 맞은 비율 |
| by_defect | 결함 종류별 탐지율 |
| recall_at_3 · mrr | RAG 검색 품질 |
| cost_usd · avg_ms | 평가 비용 · 문항당 시간 |

### 녹화 · 재생
- **live** — 실제 AI 로 평가하고 응답을 카세트에 녹화한다. 결과는 `eval_runs` 에 하네스 버전과 함께 저장.
- **replay** — 녹화된 응답으로 판정과 지표를 다시 계산한다 (AI 를 부르지 않음). 운영에서 녹화한 기준점 카세트
  (`harness/evals/cassettes/baseline.json`)를 CI 가 매번 재생해, 판정 로직이나 지표 계산이 바뀌면 숫자가 달라졌다고 알려 준다.

```sh
python -m education.harness.evals --record baseline.json   # 실제 AI 평가 + 녹화
python -m education.harness.evals --replay baseline.json   # 재생
```

### 운영 콘솔 — 하네스 평가 (`/admin#/evals`)
지표 카드(바로 앞 평가 대비 증감) · 결함 종류별 탐지율 · 평가 기록 · 문항별 판정(어느 층이 걸렀는지, 검증 AI 답, 검산 도구 호출) ·
RAG 검색 순위. '지금 평가' 버튼은 실제 AI 로 백그라운드 평가를 돌린다 (약 $1 안팎).

### 기준점 (베이스라인) — 하네스 `d3c4366f`, 2026-11-26 운영 실측

| 지표 | 값 |
|---|---|
| 망가진 문제 탐지율 | **100%** (13/13 — 정답 번호 오류 6 · 복수 정답 2 · 조건 누락 3 · 맞는 보기 없음 2) |
| 좋은 문제 오탐률 | **0%** (0/15) |
| 검증 AI 단독 탐지 / 검산 에이전트 추가 탐지 | 100% / 0% |
| 검산 에이전트 판단 정확도 | 100% (15번 실행 — 좋은 문제를 모두 '일치' 로 확인) |
| RAG recall@3 · MRR | 83% · 0.83 (6개 중 '좌극한·우극한' 질문만 다른 개념이 먼저 나옴) |
| 평가 비용 · 문항당 시간 | $0.16 · 9.8초 |

**해석**: 지금 골든셋은 검증 AI 가 혼자서도 모두 걸러 낼 만큼 쉬운 결함 위주다 (천장 효과).
검산 에이전트(Tool Calling)의 기여를 보이려면 계산이 길고 미묘한 결함(부호 · 계수 · 단위 실수)을 더 넣어야 한다 — 3단계 전에 골든셋을 어렵게 늘린다.

## 3단계 — 어려운 골든셋 · 생성 평가 · 자기 수정 루프

- **골든셋 +28**: 계산이 긴 문제 14개와, 흔한 실수 값을 정답으로 표시한 미묘한 오류 14개 (`subtle_wrong_key` — 정답·오답 모두 SymPy 로 계산).
- **생성 평가** (`golden/generate.yaml`): 개념 4개 × 3문제를 실제로 만들고 되돌린다. 첫 시도 통과율 · 시도 횟수 · 통과 문제당 비용 · 자기 수정 성공률.
- **자기 수정 루프**: 형식 · 검증 · 검산에서 떨어지면 문제 · 이유 · 검증자 답과 지적 · 도구 계산값을 다음 시도에 전달
  (`prompts/generator/repair_instructions.md`, `AI_SELF_CORRECT` 로 끔/켬 — 하네스 버전에 반영).

### 운영 실측 (2026-11-26, 평가 비용 합계 약 $1.3)

검증 (골든셋 56문항, 하네스 `7f220ef4`)

| 지표 | 28문항 기준점 | 56문항 (어려운 문제 추가) |
|---|---|---|
| 망가진 문제 탐지율 | 100% (13/13) | **100% (27/27)** — 미묘한 오류 14/14 포함 |
| 좋은 문제 오탐률 | 0% | **0% (0/29)** |
| 검증 AI 단독 / 검산 에이전트 추가 | 100% / 0% | 100% / 0% |
| 검산 에이전트 판단 정확도 | 100% (15번) | 100% (29번) |
| RAG recall@3 | 83% | 83% |
| 비용 | $0.16 | $0.32 |

생성 (12문제)

| 지표 | 자기 수정 끔 (`5fe810fc`) | 자기 수정 켬 (`7f220ef4`) |
|---|---|---|
| 통과율 · 첫 시도 통과율 | 100% · 100% | 100% · 100% |
| 문제당 시도 | 1.0 | 1.0 |
| 통과 문제당 비용 | $0.0402 | $0.0398 (차이는 오차 범위) |
| 문제당 시간 | 80초 | 78초 |

### 해석

- **지금 하네스는 천장에 있다.** gpt-6.1-sol 로 만든 문제는 12개 모두 첫 시도에 통과했고, 검증 AI 는 계산이 긴 미묘한 오류까지 혼자 모두 잡았다.
  그래서 자기 수정 루프는 한 번도 동작할 일이 없었고, 검산 에이전트의 '추가 탐지' 도 0% 다 — 두 장치는 지금 모델에서는 **안전망**으로만 남는다.
- 검산 에이전트는 29번 모두 좋은 문제를 '일치' 로 확인했다 (판단 정확도 100%, 오탐 0) — 켜 두어도 좋은 문제를 막지 않는다는 근거.
- 장치의 효과를 숫자로 보이려면 기준 모델이 실수를 해야 한다. 다음 실험: **더 작은 모델(gpt-6-luna)로 생성·검증** 하면서 자기 수정 · 검산 도구를
  끄고 켜서, '작은 모델 + 하네스' 가 '큰 모델' 에 얼마나 가까워지는지 (품질 대비 비용) 비교한다.

## 4단계 — 가드레일 + 사람 검토 (Human-in-the-loop)

### 가드레일 (`harness/guardrails.py`) — 모두 AI 없이, 규칙으로
| 층 | 하는 일 | 적용 |
|---|---|---|
| 입력 | 프롬프트 주입(지시 무시 · 역할 바꾸기 · 시스템 프롬프트 요구 · 탈옥) 표시, 개인정보(이메일 · 전화 · 주민번호 · 카드) 가림 | 대화 — 가린 글만 AI 에 보내고 저장 원문은 그대로, `guard_events` 에 기록 |
| 출력 | 수식 `$`·`{}` 짝, 빈/겹친 보기, 본문의 정답 노출, 지나친 길이, 부적절한 표현 | 문제 생성 — 검증 AI 앞의 `policy_check` 단계, 걸리면 이유를 자기 수정 루프로 되돌림 (검증 비용 절약) |
| 실행 | AI 호출 차단기(Circuit Breaker): 같은 모델이 5번 연속 실패하면 60초 동안 바로 거절 → 문제 은행 · 한 번 답으로 | `services/llm.py` 의 모든 구조화 호출 |

에이전트의 단계 상한(LangGraph `recursion_limit`), 사용량 한도(서비스 전체 하루 $20), 사용자 범위 고정 도구는 앞 단계에서 이미 있다.

### 사람 검토 큐 (`harness/review.py` → `review_items`)
- **들어오는 곳**: 학생 신고(공용 문제) · 문제 성적표 D 등급/정답 의심 · 검산 에이전트 실패(검증은 통과했지만 계산을 확인 못 함)
- **판정** (운영 콘솔 '검토 큐'): 유지(신고로 숨겨졌으면 복구) · 고른 보기로 정답 수정 · 숨김 — 관리 기록에 남는다
- **데이터 플라이휠**: 판정한 5지선다 문제는 평가 묶음 `reviewed` 로 자동으로 들어간다
  (유지 → 좋은 문제, 정답 수정 → 원래 정답 = 망가진 문제 + 고친 정답 = 좋은 문제, 숨김 → 망가진 문제).
  운영 콘솔의 '지금 평가' 는 이 묶음도 함께 돈다 — 사람이 판정할수록 골든셋이 커지고 실제 운영 문제에 가까워진다.
